# Contributing

Thanks for helping. A few things keep this project easy to work on.

## Setup

```bash
pnpm install
pnpm exec playwright install chromium   # once, for the browser tests
pnpm dev                                # the demo on http://localhost:5198
```

Node 20.19+ and the pnpm version pinned in `package.json` (`packageManager`).

## Before you push

```bash
pnpm format:check && pnpm lint && pnpm type-check && pnpm knip
pnpm test
pnpm test:e2e
```

CI runs exactly these on every pull request; a release re-runs them before publishing.

## Where things go

[docs/architecture.md](docs/architecture.md) is the map. In short:

- A **rule** (what is valid, what snaps, what a cut does) belongs in `src/core`, with a unit test
  that drives `PolygonEditorCore` or the pure function directly. The core never touches the DOM.
- **Input and drawing** on the map belong in `src/map/binding.ts`. If a change there can be
  observed by a user, add a browser test in `tests/e2e`.
- **UI** belongs in `src/vue/parts`. Every user-facing string goes in `src/vue/i18n.ts`, in English
  and Spanish. Colours come from the `--pe-*` variables, never literals.

## Principles

- **Never lose the user's work silently.** If an edit is refused, emit an `issue` and add its
  message; if a draft cannot be finished, keep it.
- **Map data helps, it does not decide.** No feature may require the basemap, the geocoder or the
  router to be right — or present.
- **Exact means exact.** Don't smooth, simplify or nudge coordinates the user placed. Anything the
  editor computes is rounded to the configured precision so it can be shared.

## Commits and pull requests

Small, focused pull requests with a clear description of the behaviour change. Conventional commit
prefixes (`feat:`, `fix:`, `docs:`, `test:`, `refactor:`, `chore:`) are appreciated.

## The demo's map data

`demo/public/data` is generated by `scripts/fetch-demo-data.sh` (needs the
[`pmtiles` CLI](https://github.com/protomaps/go-pmtiles/releases)). Regenerate it only when the demo
needs newer data; it is committed so the demo needs no network service.
